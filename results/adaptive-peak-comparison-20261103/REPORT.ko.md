# 우열 판정에 따른 조기 종료와 공유 replay

2026-11-03. 구현 커밋 `159135d`, 브랜치 `codex/selective-candidate-validation`.

## 결과와 적용 범위

같은 최종 후보의 고정된 donor 분포를 비교할 때, 이미 판정된 비교는 종료하고 겹치는 구간에만 계산을 배분하도록 구현했다. 최종 증거는 커널당 한 번씩 독립 replay한 뒤 판정한다. 기존 빠른 형상 탐색과 연속 경로 검증 코드는 변경하지 않았다.

320 donor 실험에서 새 방식은 **다섯 비교 모두를 173.65초에 판별**했다. 같은 세션에서 새로 실행한 기존 방식은 **네 비교를 335.99초에 판별**했다. 이번 관측에서는 비교 시간이 약 48.3% 감소했고 판별 수가 하나 늘었다. 새 최저 peak 형상을 찾은 것이 아니라, 같은 후보의 비교를 더 효율적으로 수행한 결과다.

이는 **같은 우열 판정 기준**의 비교다. 모든 peak 구간을 같은 폭까지 좁히는 성능 비교는 아니다. 조기 종료된 후보의 구간은 기존 방식보다 넓을 수 있다. 엄격한 구간 비중첩으로 우열을 판별하는 정확도는 유지한다. 반복 벤치마크의 통계적 가속률이나 전체 최적화의 가속률을 주장하지 않는다.

## 동일 입력과 시간 측정

이전 재검증을 통과한 여섯 커널(IMP/OMP 기준, IMP20/50, 캠페인 OMP50, 과거 OMP50)을 그대로 사용했다. 비교 대상은 후보 대 해당 기준의 네 쌍과 두 OMP50 후보 사이 한 쌍이다. source·resolution별 problem identity와 입력 파일 해시가 이전 실험과 같음을 확인했다. 기존의 명시적 unused-code audit 예외도 재검증했으며 입력 수락 기준을 완화하지 않았다.

기존 방식은 기준당 8초, 후보당 30초로 총 136초의 생성 예산을 배분한다. 새 방식은 여섯 커널이 공유하는 136초 예산에서 필요한 곳을 선택하고, 모든 비교가 판별되면 종료한다. 최종 replay는 생성 예산 밖의 필수 작업이며 총 시간에 포함한다. 예산 검사는 연산 사이에서 수행하므로 마지막 원자 연산만큼 초과할 수 있다.

| 320 donor | 기존 고정 배분 | 새 선택적 배분 |
|---|---:|---:|
| 판별된 비교 | 4 / 5 | 5 / 5 |
| 구간 생성 | 136.82 s | 84.85 s |
| 최종 replay | 198.86 s | 87.63 s |
| replay 횟수 | 10 | 6 |
| 기록된 전체 비교 시간 | 335.99 s | 173.65 s |

기존 runner의 전체 시간은 입력 audit 이후부터이며, 새 runner는 입력 audit과 소스 스냅샷 준비 0.82초도 포함한다. 생성+replay의 공통 계산 항목으로 비교해도 335.68→172.48초다. 기존 대조 실험, 새 320, 새 1280은 순차 실행했다. 전체 OS 부하를 통제한 반복 실험은 아니다.

## 320 donor 판정

| 비교 | 판정 |
|---|---|
| IMP20 대 IMP 기준 | IMP20의 peak가 낮음 |
| IMP50 대 IMP 기준 | IMP50의 peak가 낮음 |
| 캠페인 OMP50 대 OMP 기준 | 기준의 peak가 낮음 |
| 과거 OMP50 대 OMP 기준 | 과거 OMP50의 peak가 낮음 |
| 과거 OMP50 대 캠페인 OMP50 | 과거 OMP50의 peak가 낮음 |

예를 들어 IMP50의 최종 상한 2.548084가 IMP 기준 하한 2.549565보다 낮다. 과거 OMP50의 상한 2.729134가 OMP 기준 하한 2.730375보다 낮다. 수치적 감소율 전체를 이 좁은 분리 폭만으로 인증한 것은 아니며, 여기서는 개선 방향을 인증한다. 원래 해상도 재검증의 peak와 감소율은 [이전 보고서](../selective-candidate-validation-20261103/REPORT.ko.md)에 유지한다.

작업 중 기록한 최초 분리 시각은 **provisional**이다. 최종 replay가 완료되기 전에는 독립 검증이 끝난 최초 개선 시각으로 사용하지 않는다.

## 1280 donor에서의 한계

여섯 커널·다섯 비교에 공유 생성 예산 136초를 적용하면 **0/5개 판별**이었다. 생성 136.12초, 최종 replay 135.21초, 준비·출력을 포함한 전체 272.54초였다. 생성 예산 초과는 0.12초, 완료한 연산은 218개였다. 이전 고정 배분 실험도 0/5개였으므로, 고해상도에서 후보 우열을 판별하는 성능이 개선됐다고 주장하지 않는다. 이 예산에서는 후보 수를 줄여 집중하는 방법을 추가로 평가할 필요가 있다. 예산 확대나 다른 배분 전략도 가능한 대안이다.

별도 진단으로 과거 OMP50과 OMP 기준 **한 쌍만** 같은 1280 donor 모델과 136초 생성 예산에 넣었다. 생성 62.24초에 조기 종료했고, 독립 replay 61.78초와 준비·출력을 포함해 **125.23초에 개선을 판별**했다. 후보 상한 2.715447이 기준 하한 2.725487보다 낮다. 다른 네 비교를 수행하지 않은 결과이므로 다섯 쌍 전체의 속도 향상으로 합산하지 않는다. 이번 사례에서는 수치적으로 유망한 소수 후보만 높은 해상도로 올리는 단계적 사용이 실용적이었다.

## 구현과 검증

- `PeakBuilder`가 원본 모델을 복사해 소유하고 기존의 directed-rounding probe/split을 한 번씩 이어서 수행한다. 기존 v1 증거 형식과 replay를 그대로 사용한다.
- 현재 구간 폭과 미해결 비교의 연결 수를 곱해 다음 커널을 선택한다. 이 점수는 계산 순서의 휴리스틱이며 증명의 일부가 아니다. 판정된 비교의 참여자는 다른 미해결 비교가 없는 한 더 세분화하지 않는다.
- 최종 증거를 커널당 한 번 replay하고, 소유했던 모델·problem identity와 일치하는지 확인한 뒤 최종 판정을 다시 계산한다. 외부 성공 플래그나 검증되지 않은 영속 캐시를 신뢰하지 않는다.
- 0초 예산에서는 세분화하지 않는다. 초기 보편 구간만으로 분리되면 판정할 수 있고, 겹치면 미해결로 남긴다. 좌표 정밀도 한계에서도 기존 유효 분할을 보존한다.
- 모델/반환 증거의 변경 격리, 근접 후보, 잘못된 identity, 변조된 최종 증거, replay 실패, 시간 초과와 연산 예산을 검사했다. 기존 회귀검사를 포함해 **209개 테스트**가 통과했고 독립 설계·코드 검토를 마쳤다.

권장 사용 순서는 기존 빠른 탐색 → 수치·형상 재검증 → 320 donor 후보 비교 → 유망한 소수 후보만 1280 donor 비교다. 다음에는 이 순서를 실제 최종 후보 선택에 연결하고, 준비 비용 재사용을 포함한 총 소요시간을 측정한다. 320 판정을 1280이나 연속 경로의 증명으로 승격하지 않는다. 연속 경로 구간 축소와 전역 최적성 인증을 탐색 루프의 필수 조건으로 넣지 않는다. 본 결과는 유한한 고정 수치 커널의 peak 순서이며, 연속 경로·연속 source·전역 최적성의 증명이 아니다.
